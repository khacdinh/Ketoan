# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

"Kế Toán Công Trình" (formerly "Sổ Thu Chi"; branded with the Điền Thủy company logo in `public/img/`) — a local, offline, single-user accounting app (Vietnamese UI) with two parts that mirror two Excel workbooks: the cash book ("Quản lý thu chi": `Tong_Quan`, `So_Thu_Chi_Hang_Ngay`, `Phieu_Chi`, `Danh_Muc_Du_An`, `Danh_Muc_NCC`, `Tong_Hop_NCC`) and construction costs ("ChiPhi_CongTrinh": `PHIEU_NHAP`, `NHATKYCHUNG`, `TONGHOP`, `CHI_TIET_THEO_NHOM`, `CONGNO_NCC`, `DM_*`; the `DUTOAN` estimates sheet was deliberately dropped at the user's request and is ignored on import). Plain Node.js HTTP server + vanilla JS frontend; no framework, no bundler. The only runtime dependency is `exceljs`. End users launch it with `KhoiDong.bat` (`TaoBieuTuongDesktop.bat` → `scripts/tao-bieu-tuong.ps1`, must stay UTF-8 with BOM, creates a Desktop shortcut "Kế Toán Công Trình" with `public/img/bieu-tuong.ico`); `HUONG_DAN_SU_DUNG.md` is the end-user manual (Vietnamese).

Code identifiers, comments, UI strings and error messages are in Vietnamese — keep it that way (user-facing wording always says **Công trình**, never "Dự án", even though code/fields keep `maDuAn`/`projects`; Excel headers keep the original workbook's `Mã Dự Án` so files re-import) (e.g. `thu`/`chi` = income/expense, `ton` = running cash balance, `maDuAn` = project code, `maNCC` = supplier code, `soPhieu` = voucher number, `nganSach` = budget; cost side: `maCT` = công trình = project code, `maNha` = house, `maHM` = hạng mục/cost item, `maNhom` = cost group, `maVT` = material, `loaiCP` = cost type, `soLuong`×`donGia`=`thanhTien`).

## Commands

```bash
npm start                 # node server.js — listens on 127.0.0.1:3939 and opens the browser
node server.js --no-open  # don't open a browser (also NO_OPEN=1)
npm run build             # build:assets + build:css — run after changing UI markup/classes/icons
npm run watch:css         # Tailwind watch while editing UI
```

Env vars: `PORT` (default 3939; auto-increments up to 20 ports if busy, and if the port is already held by this app it just opens the browser and exits), `KETOAN_DATA` (data directory, default `./data`). Use `KETOAN_DATA` pointing at a scratch dir when experimenting so the real `data/` isn't touched (starting the server on `data/` migrates `ketoan.json` → `ketoan.db` and renames the JSON; `data/` is tracked in git — never commit those changes).

No linter is configured. `npm test` runs `tests/*.test.js` with `node --test` (real server on a random port + scratch data dir; no extra dependencies). Groups: `a-` environment/startup, `b-` storage/backup/constraints, `s1…s5-` SQLite migration/robustness/backup+security/performance/environment, `c-` business regression (`c-giao-dien` drives Chromium via a globally installed Playwright and is skipped without it), `e-` Excel import/export and reconciliation (LibreOffice recalculation is skipped without `soffice`; `RUN_NPM_INSTALL=1` also runs the clean-install test). Frozen data fixtures are in `tests/fixtures/`. To reconcile against the real cost workbook run `node tests/doi-chieu-xlsm.js <file.xlsm>`.

## Architecture

**Shared calculation module — `public/js/shared.js`.** UMD file loaded both as `window.KT` in the browser (classic `<script>`) and via `require` on the server (`server.js`, `lib/importer.js`, `lib/exporter.js`). All business math lives here — amount parsing (`parseAmount` accepts `1.250.000`, `50tr`, `300k`, `58000+11000`), money-in-words (`docTienBangChu`, matching the original Excel formula), running balance (`buildLedger`), filtering, project/supplier summaries, voucher grouping (`buildVouchers`), next voucher number. UI, printed vouchers and Excel exports must all go through these functions so the numbers agree. Keep it dependency-free and ES5-ish-compatible with both environments (no `import`/`export`).

**Server — `server.js`.** Single `http` server, hand-rolled routing in `handleApi`. Every mutating endpoint validates input via `cleanEntry`/`cleanProject`/`cleanSupplier`, mutates `store.db` in memory, calls `store.save()`, and **responds with the entire DB** (`ok()` → `{ ok: true, db }`). API requests with a non-localhost `Origin` are rejected. Renaming a project/supplier code cascades to all entries; deleting one that's in use is refused.

**Storage — `lib/store.js` + `lib/db.js` (SQLite, `node:sqlite` `DatabaseSync`).** Data lives in `data/ketoan.db`; design in `docs/THIET_KE_SQLITE.md`. The rest of the code still works on one in-memory object `store.db` (same shape as the old JSON plus schema-5/7 lists: `{ schema, settings, projects, suppliers, entries, vouchers, costGroups, costItems, materials, houses, costs, trash, locks, ignoredWarnings, cashCounts, attachments, extPayments, soDuDauKy, aliases, mergeLog, ignoredDupes, nextId }`; a missing `trangThai` means posted) — handlers mutate it and call `store.save()`, which diffs every record against a snapshot of the last commit and writes only changed rows in ONE transaction (`BEGIN IMMEDIATE`). On failure it rolls back and rebuilds `store.db` from the snapshot (`rollbackMemory`), so memory always equals disk; a commit by another process (PRAGMA data_version) → 409 + reload. `replaceAll(db, reason)` = backup + clear + insert all in one transaction. Tables are STRICT with one typed column per known field (names = JS field names), `vt` = array position, `khac` = JSON for anything that doesn't fit (unknown fields, null, wrong types, strings with NUL — node:sqlite < 24.16 truncates NUL in TEXT). Code columns store `''` as NULL. No FKs on codes (the app matches codes case-insensitively via `KT.keyOf` and tolerates unknown codes). `PRAGMA user_version` = `DB_VERSION` = 7 (`MIN_VERSION` 4). Tables/columns carry a `since` version; opening an older file backs it up (`truoc-nang-cap-luoc-do-<n>`, kept forever) and `SqliteDb.migrate()` adds missing tables/columns in one transaction (idempotent). For future changes bump `DB_VERSION` and mark new tables/columns with `since`. First start with only `ketoan.json` → `migrateFromJson()` (backup `truoc-khi-chuyen-sqlite`, temp `ketoan.db.dang-chuyen`, verify with `lib/migrate.js` `soLieu`/`canon` before COMMIT, rename, report `data/migrate-bao-cao.txt`); on any mismatch it throws and the server exits, leaving the JSON untouched. Backups: `VACUUM INTO` → `data/backups/ketoan-<stamp>-<reason>.db` (max 1 per 10 min during edits, always before import/restore/reset; keeps 60); old `.json` backups are still listed/restorable. `normalize()` repairs missing ids/`seq` (importers can push records with `id: 0` and call `replaceAll`); `save()` also assigns ids to records pushed with id 0. Entries are ordered by `ngay` then `seq`; `id` is global across all lists. `vouchers` is a map of voucher-number (uppercased) → print overrides only; vouchers themselves are derived by grouping entries with the same `soPhieu` (prefix `PT` = receipt/thu, otherwise payment/chi). Requires Node ≥ 24.16.0 or ≥ 26.1.0 (`lib/node-version.js`; `KETOAN_CHO_NODE_CU=1` bypasses for tests — `tests/helpers.js` sets it). Tests read persisted data with `readStored(dir)` / `readBackupFile(f)` from `tests/helpers.js`; `node tests/doi-chieu-sqlite.js --goc <JSON-version checkout>` reconciles against the old JSON build.

**Frontend — `public/`.** `index.html` loads `shared.js` then ES module `js/app.js`. Hash router (`#/so-thu-chi`, etc.) in `app.js` maps routes to `render*` functions in `js/views/*.js`, each re-rendering `#view` via HTML strings (always escape with `esc()` from `ui.js`). `ui.js` `api()` wraps `fetch`; whenever a response contains `db`, it calls `setDb` (`state.js`), which recomputes the ledger and re-renders the current view — so views never patch local state after a mutation. Filters persist in `localStorage` under the `stc.` prefix. `forms.js` = entry form + catalog modals (the Ghi thu/chi form is a PAGE, route `#/ghi-thu-chi` → `renderEntryPage`; `openEntryForm(entry, opts)` stores the request and navigates to `#/ghi-thu-chi?k=<n>`, Hủy/Esc/Ghi sổ go back to the previous hash, and a re-render with the same `k` keeps the DOM so data reloads don't wipe typing; UI tests address it as `#entry-page`. It is a multi-line voucher: shared header + `#phieu-dong` table, one entry per row sharing `soPhieu`, each with its own `maDuAn`/`maVT`/amount so supplier debt splits per project; row 1 keeps the legacy `name=` attributes and `#da-hint/#vt-hint/#chi-hint/#thu-hint` ids, all rows carry `data-c`; one row saves via the old POST/PUT, several rows or removed rows via `POST /api/entries/phieu { rows:[{id?,…}], xoa:[ids] }` — atomic, validates every row first, locks/audit/trash; the form's 'Sửa cả phiếu' link reopens with `opts.phieu`), `print.js` = A4 two-copy ("2 liên") voucher printing. **Shell (Industry redesign):** `index.html` = sidebar 248px / 56px collapsed (`#nav` built by `app.js` `NAV` groups; each item `[route, 'ph-<lucide-name>', label, key hint, tab]` — icon names must be written literally with the `ph-` prefix so `build-assets` finds them; no 2-letter codes; collapsed state stored per user in `LS side-thu[.<userId>]`; `@ghi-thu-chi` item opens the entry dialog; F2 = `#/cp-nhap`, F3 = Ghi thu/chi, Ctrl K `search.js`, Ctrl B collapse, Ctrl L `auth.khoaManHinh`) + topbar (`ctpick.js`: global project `S.ct` is the ONLY công trình filter — written through to `so.duAn` and the `cpSo/cpTh/cpCt/cpCn` filters; `'__none__'` = "Chưa gán công trình", offered only on Sổ quỹ and treated as all on cost pages; the button is hidden outside `CT_ROUTES`; code that navigates to a filtered Sổ quỹ must call `datCongTrinh(ma, true)` instead of setting `so.duAn`) + `.page-head` (`setPageActions`, `setPageTitle`, `setPageTags` in `ui.js` let a view own the header buttons; `app.js` resets them every route) + `#bottom-nav` on phones (≤767px; phone layout is basic and deliberately out of the tested scope — the user said it needs no further work). Unified period bar `periodControls/bindPeriodControls/syncPeriodControls` (`ui.js`; filter state `{period: thang|quy|nam|khoang|tat-ca, from, to, rel}`, old values like `thang-nay` are normalised by `refreshPeriod`; `KT.periodUnit/periodShift/periodLabel`). `ui.js` also holds density (`datMau`, body `data-density`) and the offline/auto-retry bar. Debt screens: `views/debt.js` (route `cp-cong-no`, `tong-hop-ncc` aliases it; uses `KT.supplierPeriod`), `views/supplier-ledger.js` (`so-chi-tiet-ncc`, data from `congno.js` `soChiTiet`), `bienban.js` (A4 reconciliation minutes, `print.js` `printHtml`/`printSlip`), `congno.js` (Dư Có / Dư Nợ display helpers, `hauQuaCongNo` for delete confirmations), `khoa.js` (locked-period dialog). **Excel — `lib/importer.js`, `lib/exporter.js`, `lib/chart.js`.** Importer recognises columns by header text (so both the original workbook and this app's own exports re-import) and supports dry-run preview, `replace` and `merge`. **Construction costs (chi phí công trình).** Projects and suppliers are shared with the cash book (a công trình *is* a project; no duplicate tables). Cost rows store only codes; names, group, unit are always looked up from catalogs (`KT.buildCostLedger`), so renaming a catalog entry updates every report. A phiếu nhập is the set of rows sharing `phieuId` (allocated from `store.newId()`). A slip can span several công trình: the UI header has no công trình/nhà any more (only Ngày, NCC, Số phiếu) and every line carries its own `maCT` (+`maNha`, columns Công trình/Nhà / khu, new lines copy them from the line above); the server still accepts a header `maCT` as a default for API callers (`cost-entry.js` line field `ct`, column "Công trình"; `KT.costSlips` exposes `dsCT`). `cleanLine` also derives `maHM` from the material's own `maHM` whenever the line has a `maVT` whose material is linked to a cost item (the line's/header's `maHM` is only used for lines without a material or with an unlinked one) so a material can never sit under two hạng mục/nhóm; the slip grid has no hạng mục input at all (no header field; a read-only "Nhóm › Hạng mục" column `.vt-hm` from the material) and every new line must have a material linked to a cost item (old lines without one keep their stored `maHM` via line field `hmCu`); the material form makes Hạng mục required; changing/assigning a material's `maHM` (PUT `/api/materials/:id`) rewrites `maHM` on all its cost rows outside locked months (response `theoHM`). The slip grid has no Loại CP column either: `loaiCP` is left to the server default (`KT.defaultLoaiCP` from the material, then the cost item). All cost math is in `shared.js` (`costAmount` = integer-safe SL×ĐG, `costFromInput` = SL/ĐG/Thành tiền from user input — TT-only lines ("theo khoản": labour, fees, a retail invoice recorded as one total) are stored with `soLuong`/`donGia` = **null** and only `thanhTien` (never fake SL 1 × ĐG = TT; `KT.isKhoan(c)`); every other line keeps SL×ĐG=TT. Old-style khoản rows (SL 1 × ĐG = TT, `KT.laKhoanCu`) are converted on Excel import and on demand via `POST /api/costs/theo-khoan` (Chủ, action `sua-hang-loat`; banner in Sổ chi phí). Price stats/history/last-price skip khoản lines, the exporter writes their Thành tiền as a plain value instead of the `ROUND(SL*ĐG)` formula, and importers read TT-only rows back as khoản (dedupe key uses `thanhTien` for them), `costSummary`, `supplierDebt` = cost rows − (cash-book chi − thu) joined by `maNCC` and optionally `maCT`=`maDuAn`, `materialStats`, `priceHistory`, `lastPrice`, `costSlips`). `lib/costApi.js` holds catalog CRUD with rename cascades/delete guards (`REFS`), slip and row endpoints; `server.js` delegates to it and also calls its `cascadeRename`/`usages` for projects/suppliers. `lib/costImporter.js` is tried first in `/api/import` (returns null for non-cost workbooks); it recomputes formula columns, maps file CT codes to existing projects, dedupes as a multiset, and optionally imports `SO_QUY` into the cash book. `lib/costExporter.js` writes the ChiPhi_CongTrinh layout with live SUMIFS/INDEX-MATCH formulas and re-imports cleanly; it post-processes `<sheetPr>` child order because ExcelJS emits `outlinePr` after `pageSetUpPr` (Excel refuses to open the file otherwise). Frontend views: `views/cost-entry.js` (multi-row grid, keeps an in-progress draft in `localStorage` because every `setDb` re-renders the route), `cost-ledger.js`, `cost-reports.js`, `cost-catalogs.js` (tab Vật tư = left tree `#dm-tree` "Khoản mục chi phí" groups → items built by `vtTree`, selection in `cpDm.vtSel` `''`/`g:<nhóm>`/`h:<hạng mục>` (`h:` = no hạng mục), open groups `cpDm.vtMo`; right `#dm-table` filtered by it; `menuTabDanhMuc` decides which of the two sidebar items is active; tests `tests/w-danh-muc-vat-tu.test.js`).

When verifying Excel output, open it in real Excel (COM automation via PowerShell works on this machine) — ExcelJS will happily write files Excel cannot open.

`So Thu Chi UI.html` is a large bundled design mockup, not part of the running app.

**Traceability (group 1) — `lib/audit.js`, `lib/traceApi.js`, `lib/cashCountApi.js`, `lib/attachApi.js`.** Audit log is append-only `data/nhat-ky.jsonl` (not inside ketoan.json; restores never erase it); handlers call `trace.log(...)` before `store.save()` (pending entries flush after the file is written). Every delete goes through `trace.toTrash` (records leave the live arrays, so reports need no filtering; attachments of trashed records travel with the trash item). `ok()` sends `store.publicDb()` (no `trash`). Drafts: `trangThai: 'nhap'` on entries/costs; reports use `KT.postedDb(db)` (returns the same object when there are no drafts) — on the client `S.db` is the posted view and `S.all` the full data (use `S.all` to find records for editing). Month locks: `trace.assertOpen(dates, verb)` (HTTP 423) on every mutation; importers skip locked months. Anomalies: `KT.anomalies(db)` (client-side, cached per data version in `state.js`; groups `trung/gia/ngay/vt/thieu/nhap/tien/quy` plus `congno` (supplier debt: payment without/wrong công trình — valid pairs come from costs, soDuDauKy and extPayments —, overpaid, long unpaid aged FIFO over costs + positive opening balances — target kind `ncc` opens Sổ chi tiết NCC unfiltered, period all), `thuchi` (voucher-type mismatch, chi without số phiếu, big chi without NCC/công trình (threshold 0 allowed), negative END-OF-DAY balance), `chiphi` (hạng mục ≠ material's, missing công trình, TT ≠ SL×ĐG); thresholds `soNgayNoLau`, `nguongChiLon` in settings; tests `tests/z-canh-bao-moi.test.js`). Attachments live in `data/attachments/<yyyy-mm>/<id>-<hex>.<ext>` (names generated server-side, content-sniffed — images, PDF, Word/Excel docx/xlsx/doc/xls, macro files refused, Office files always served as downloads — `wx` writes). A new cost slip keeps chosen files in memory (`attach.js` `pendingBlock`) and uploads them right after the slip is saved. UI: route `#/kiem-soat` (`views/control.js`) with tabs Cần xử lý / Kiểm quỹ / Khóa sổ / Nhật ký / Thùng rác. Baseline figures before group 1: `tests/fixtures/moc-so-lieu-nhom1.json` (ca N0).

**Code merging (gộp mã) — `lib/mergeApi.js`, `lib/aliasImport.js`, `public/js/merge.js`, `public/js/combo.js`.** Five code kinds (`LOAI`: `ncc` suppliers, `vt` materials, `hm` costItems, `nha` houses, `da` projects), each with the `[list, field]` references it rewrites (incl. `extPayments`, trash records, and `vt:`/`thieu:` ignoredWarnings keys). A merge only rewrites code fields (never amounts or `updatedAt`), marks source catalog records `gopVao: <target>` (kept, hidden: use `KT.activeDb(db)` for anything user-facing/exported, `KT.isMerged`), adds `aliases` rows, and logs every change tuple `[list, id, field, from, to, trashId?]` in `mergeLog` so undo can verify (`undoCheck`: later merges touching the same codes, records edited since) and revert exactly. All in one `store.save()` after a `truoc-gop-ma` backup. `KT.resolveAlias`/`aliasIndex` map old codes → target: server `findCode` and `KT.findCostItem` use them for typed input; `lib/aliasImport.js` rewrites codes in parsed Excel before dry-run/apply and reports file/sheet/row/column; `state.js` `remapSavedCodes` fixes saved filters. Split (`tach-hm`) moves a filtered/selected set of cost rows to another (optionally newly created) cost item. Suggestions (`/api/merge/suggest`) never merge on their own. Catalog screens use `mergeToolbarHtml`/`pickCell`/`bindMergeUI`; route `#/gop-ma` has log/undo, suggestions, split. Tests: `tests/m-gop-ma*.test.js` (M0–M14, MU1–MU5) with independent invariant checks (`soLieu`, `checkInvariant`, `noOrphans`, `sameData`).

**Supplier opening balances (số dư đầu kỳ NCC) — `lib/soDuDauApi.js`, `public/js/sodudau.js`.** Schema 7 list `soDuDauKy` rows `{ ngay, maNCC, maDuAn, soTien, ghiChu }` (signed: + = we owe the supplier, − = advance) for debt that predates the books. `KT.supplierDebt` adds them as `dauKy` (`conLai = dauKy + phatSinh − daTra`; counted when `ngay <= f.to`); `KT.supplierPeriod(db, { from, to, ct, ncc })` gives per-supplier Đầu kỳ / Phát sinh trong kỳ / Thanh toán trong kỳ / Cuối kỳ (Tổng hợp NCC screen + `/api/export/suppliers`; cuối kỳ always equals `supplierDebt` conLai at `to`). Same rules as extPayments (locks, audit, trash, rename/merge refs, `/api/so-du-dau` in `ROUTES`); Excel sheet `SO_DU_DAU_NCC` (CONGNO_NCC column C sums it) re-imports via `lib/costImporter.js`. Tests: `tests/y-so-du-dau-ncc.test.js`.

**Off-fund supplier payments (trả NCC từ nguồn khác) — `lib/extPayApi.js`, `public/js/extpay.js`.** `extPayments` rows `{ ngay, maNCC, maDuAn, soTien, nguon, ghiChu }` count toward `daTra` in `KT.supplierDebt`/`projectDebtSummary` (`daTraNgoai`, `daTraQuy`) but never touch the cash book or running balance. Respect locks, audit, trash; exported as sheet `TRA_NGOAI_QUY` (cost workbook formulas add it) and re-imported by `lib/costImporter.js`. Tests: `tests/x-tra-ngoai-quy.test.js`.


**Login & permissions (đăng nhập, phân quyền) — `lib/auth.js`, `lib/quyen.js`, `lib/matKhau.js`, `public/js/auth.js`, `views/users.js`.** OFF by default; when off, `auth.xacThuc` returns immediately and nothing changes (keep it that way — all old tests run with it off). Auth tables (`nguoiDung`, `phienDangNhap`, `suKienBaoMat`, `cauHinhDangNhap`; `AUTH_SQL` in `lib/db.js`) live in `ketoan.db` but OUTSIDE `TABLES`/`store.db`: accessed only through parameterized SQL in `lib/auth.js`, so they never reach `/api/db`, exports or `readDbFile`, and restores never overwrite them; `snapshotBuffer({ boXacThuc: true })` strips them from downloaded backups. Config (`bat`, `thoiGian`, …) is cached in memory. `lib/quyen.js` is the single permission matrix: every `/api/*` route must be listed in `ROUTES` with an action from `HANH_DONG` (deny-by-default 403 `CHUA_KHAI_BAO` when on); `tests/q-ma-tran-quyen.test.js` scans the server source for routes and fails on any undeclared or stale entry — **adding an API route means adding a line to `ROUTES`**. Roles `chu` / `ke-toan` / `chi-xem`; unclear/destructive actions go to `chu`. Sessions: random 32-byte token in cookie `stc_phien` (HttpOnly, SameSite=Strict), only SHA-256 stored; non-GET requires same-origin Origin/Referer; responses carry `X-Phien-Con-Lai` for the client's 2-minute expiry warning. Actor: `AsyncLocalStorage` (`auth.als`) → `store.nguoiThaoTac` stamps `nguoiTao` on new records in `save()`/`replaceAll(…, { danDauMoi: true })`; `trace.log` stamps `nguoiTao`/`nguoiSua` (user id as string, `'Người dùng máy này'` when off, missing = "Dữ liệu cũ"). Never log/return passwords, session tokens or recovery codes. Recovery: one-time code written to `data/khoi-phuc/MA_KHOI_PHUC.txt`, Chủ backup code, CLI `scripts/dat-lai-mat-khau-chu.js`. Tests: `tests/k-*.test.js`, `q-ma-tran-quyen`, `u-dang-nhap-ui`; helpers in `tests/auth-helpers.js` (fake server clock via `KETOAN_DONG_HO_GIA`). Report: `BAO_CAO_DANG_NHAP.md`.
